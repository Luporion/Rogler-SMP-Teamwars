# Rogler Core – aktueller Projektstatus

**Stand 8. November 2026 – v0.8.4 SOURCE CANDIDATE.** Ausgangspunkt ist das am 31.10.2026 nachweislich erfolgreich gebaute v0.8.3 (`feat/v0.8.3-update`, Commit `c368b1f8`; Core `41144210216`, NeoForge `41144210282`). v0.8.4 besitzt **keinen eigenen nachgewiesenen Gradle-/NeoForge-Build und keine Gameplay-Freigabe**.

**Neu in v0.8.4:** Control Center 2.0 mit paginierten, serverautorisierten OP-Team-/Core- und Raidansichten, direkter Diagnose-Statusseite, Audit-Log und sicheren Admin-Befehls-IDs (keine frei gesendeten Client-Kommandos). Alle 24 bisher unterstützten Rogler-Properties werden nun per Vergleich des angezeigten/aktuellen Werts geschrieben, wodurch veraltete Bearbeitungen abgewiesen werden. Scheitert der anschliessende Modul-Reload, versucht die UI den vorherigen Datei-Wert wiederherzustellen; dies ersetzt kein Weltbackup. OP4 fuer kritische Raid-/Core-Aktionen, OP2 fuer Lesen; alte Command-Permissions gelten weiter. [Release v0.8.4](releases/v0.8.4.md) und [UI-Handbuch](UI_CONTROL_CENTER.md).

**Erfolgreich getestet:** existierende pure Java Regressionstests (Teams, Base, Waypoints, v0.8.2 UI), 91 neue `AdminActionPolicyTests`, statische Schutzchecks fuer v0.8.4 sowie v0.8.3 C2ME-Sicherheit und sechs Create-Stubchecks. Tests wurden im isolierten Quellcode-Entwicklungsumfeld ausgefuehrt; dies beweist keinen NeoForge-API-Build oder Ingame-Funktion.

**Unverändert:** BlockEntity-Speichern und Create-Speed-Abfrage in v0.8.3 ohne Chunk-/World-Lookup, `owner()` nur geladene Chunks; keine neuen SavedData-Schemas, keine neuen Pflichtmods, alte Core-Inventare und Teams unangetastet. Der urspruengliche Watchdog vom 30.10.2026 zeigte `CoreKineticBlockEntity.write -> enabled -> CoreInfrastructureService.owner -> getBlockState -> getChunk`. Der v0.8.3-Fix hat diese Stelle im Code beseitigt, **reale Dauerstabilitaet muss trotzdem belegt werden**.

**Offen vor Produktivfreigabe:** v0.8.4 NeoForge-CI/Modversion, Start/Join mit zwei FTB-Teams samt OP2/OP4/Nicht-OP, GUI-Layout bei verschiedenen Skalen, korrekte Sicht-/Rechtefilterung inklusive OP, sichere Audit-Persistenz/Rotation, CAS-Konflikt bei zwei Admins, Create/C2ME Chunk-Unload, v0.8.1 Waypoint-Move/Delete-/AutoMetadaten-Regression. Mehr Features wie vollwertige FTB-Team-Mutationsverwaltung, detailreicher Diagnosebericht oder erzwungene FTB-Teamlimits fehlen und werden **nicht als fertig bezeichnet**.

**Nicht Teil von v0.8.4:** Gemeinsame Xaero-Geländekacheln, eigener Core-Chunkloader, Teamfunk, echte AE2-ME-Speicherknoten, Sophisticated-Modulsockets, Itemmarkt, Events und mobile Sable-Basen. Fork-Kandidat fuer Shared Exploration bleibt Xaero's Maps: Multiplayer+; bewusst nach UI-/Stabilitaetsphase.

Technik: Minecraft 1.21.1, NeoForge 21.1.249, Create 6.0.10, FTB Teams 2101.1.11, FTB Chunks 2101.1.22, FTB Library 2101.1.37, Xaero Minimap 26.4.2, World Map 1.45.0. FTB `long_range_tracker_interval: 0` und private Team-Visibility bis Security-Abnahme beibehalten. [Testmatrix](TEST_MATRIX.md) · [Roadmap](ROADMAP.md).
