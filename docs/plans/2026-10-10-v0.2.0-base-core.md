# v0.2.0 — physical Base Core MVP

Target: maintain backward compatibility with v0.1.0 team privacy, introduce FIRST server-validated physical core, NOT complete base defense.

## Done in SOURCE
- Register Base Core block and associated `BlockItem` with a custom per-team token.
- OP issue command, strict FTB party membership and one issued/placed/escrow core per party.
- Block placement limited to the Overworld ring; default 300–2000 blocks from worldspawn.
- Stop arbitrary world block breaking via event + high hardness. Server does not trust name/creative copies.
- Save state in Overworld SavedData; reject duplicate persisted team/token identities.
- Count active on-player inventory carry time in 1s steps; after 3600s attempt permitted auto-placement using vanilla BlockItem events if held; otherwise invalidate token and enter admin escrow. Pause timer without active teammate carrier.
- Actionbar distance and remaining time, warnings near/outside zone, `/teamwars base distance`.
- Separate admin-only diagnostics with no enemy base coordinate leak.
- 25 new pure Java assertions, 64 previous assertions retained; CI compile workflow for Java/NeoForge.

## Hard acceptance gates before MVP gameplay
1. CI `NeoForge v0.2.0 Compile` must produce JAR using Gradle 8.14, Java 21.
2. In disposable world with FTB Teams 2101.1.11 and FTB Library:
   - OP `/teamwars admin issuecore <player>` with a party player => ONE signed item; repeated issue rejected.
   - Player `/teamwars base distance`; normal `/teamwars base status` reveals only own core.
   - Try first illegal placement at radius <300, >2000, Nether; then valid Overworld placement 300..2000.
   - Copies `/give roglerteamwars:base_core` must fail; duplicate signed stacks cannot both place.
   - Save-restart, FTB party leave/join/kick, offline handling, creative mode/permissions, death/containers, and other mods trying to move blocks.
   - Force timer test with staging `carry_seconds=60` *before* a core is issued. Confirm held-item auto place with clear support; safe escrow on failure.
   - Multiplayer client and server startup; verify no critical log errors.
3. Backup test world before enabling the new item in any long-lived server.

## Open / deferred (do NOT mark done)
- A proper wall-like rendered outer border and Xaero zone circles.
- FTB Chunks team claims, separate force-loaded budget, Grace Period, raid immunity.
- Automatically restoring item at last-safe coordinate *without* cheating claim placement hooks. Safe escrow is interim.
- Creative/commands/explosion and movable-contraption bypass audit for block immutability.
- Base inventory, Sophisticated upgrades, team naming fees.
- Ship attachment and 10m nuke countdown.

## Known constraints
- Existing core blocks cannot be picked up normally; future controlled relocation command is required.
- Admin must explicitly recover expired escrow; discarded inventory core may require operator intervention.
- Serverconfig radius parameters are effectively world-creation settings. Do not change after issuing the first core without a migration; the store validates recorded legal positions.
- Only a signed carrier item counts down; storage containers do not. Logout pauses.
- This is not raid-ready and not yet server-runtime-tested as source code.
