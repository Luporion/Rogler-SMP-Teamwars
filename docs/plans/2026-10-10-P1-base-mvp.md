# P1: First Minecraft-usable base MVP (Saturday 2026-10-10)

**Objective:** a REAL NeoForge server+client JAR with enforceable team, base placement and one-per-team state, tested on throwaway world. P0 Java core currently exists but is NOT a mod implementation.

## Implementation order (one branch / PR per short task)

### P1.0 Build gate (must finish first)
- Get official NeoForge 1.21.1 MDK wrapper files, validate repo's `mod-neoforge/build.gradle`/mods.toml, `gradlew build` against 21.1.249.
- Run disposable NeoForge profile with only minimal dependencies; `/teamwars status` works, then test with full pack, record startup logs.
- Add documented wrapper (checked-in official JAR allowed), CI Minecraft compile job if stable. Update PROJECT_STATE.

### P1.1 Team binding
- Read current FTB Team member UUID list and subscribe to membership events OR reconcile after each join and server startup.
- Team identity maps FTB party UUID (or stable derived UUID) to TeamWars UUID. Protect against team name changes, repeated creation, dissolution.
- Gate team creation and size (max team size configurable, default 4). Check FTB 2101.1.11 validator method.
- Test: join, leave, kick, rename, death, disconnect, relog, restart; no lost/orphaned UUID.
- If event API unavailable, use low-frequency reconciliation, not per-tick full scan.

### P1.2 Core block registration + durable identity
- Register block/item/block entity & menu if needed; server creates exactly one canonical core ID per team.
- Core ownership is **not** trusted from client NBT, block item names, or GUI.
- Persist core UUID, team UUID, lifecycle Snapshot, last verified legal placement, inventory escrow key.
- Keep one live canonical core across dead player, container, item drop, chunk unloading, death, player transfer; recover after crash and invalid NBT.
- Test two copies crafted/creative/cloned: only one can become active, other invalid.

### P1.3 Placement and transport
- Hook right-click placement and periodic server 1-second tick (accumulate elapsed online seconds). Verify dimension + radial range and surface/block replacement/world protection; inform carrier through action bar.
- At 3600s: request auto placement or last **verified** safe return; if invalid use escrow + admin alert, NEVER drop/overwrite arbitrarily.
- Rate limit state writes; persist every minute and before logout/dimension change; snapshots self-consistent.
- Test nether, spawn <300, edge exactly 2000, outside >2000, carrying across logout, death, inventories.

### P1.4 Protected base / FTB claims
- Bind core area to team FTB Chunks claims. Distinguish claim creation on initial placement, movement, destruction, release; use API events, not raw config file rewriting.
- Only team members can build in protected area while grace active. Do not blanket-enable explosions until raid logic verified.
- If FTB core-vs-manual quota API insufficient, temporarily use one conservative shared quota and document deferral.
- Add config toggles and logging for radius / grace / base limits.

### P1.5 Smoke / artifact
- Test actual JAR in full 524-mod profile on fresh world, with 2 players. Screenshot, latest.log, permissions matrix, restart test, TPS baseline.
- Build checksum and tag `v0.1.0-mvp` only when functioning in staging.

## Definition of done
All required server-state invariants hold; no duplicate cores; no unauthorized placement/removal; joining/removing team doesn't break claims; save/restart tested; at least one raid-control path; server log contains no new critical errors. Document excluded features explicitly.

## Explicitly excluded from P1 deadline path
Full shared Xaero map terrain + revoke (continue separate spike), Marketplace, Sable Nuke, AE2 & Sophisticated inventory upgrades, Chunky Friends extension. These MUST NOT block playable team/base foundation.
