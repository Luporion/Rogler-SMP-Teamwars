# v0.6.2 implementation plan (completed as source candidate)

Problem: TeamWars v0.6.0/0.6.1 `onExplosion` performed core-ledger owner lookup for each impacted BlockPos in Warium nuclear blast. Repeated third-party block removal could also continuously reconstruct an active core. FTB auto-managed receipt could persist for absent/foreign claims.

Solution: 1) reusable pure Java primitive position-index projection built per explosion event, no chunk loading and no stale cache; 2) bounding repeated auto-reconstruction through a five-second observation period and max 2 retries per 2 minutes, ESCROW and tracked claim cleanup; 3) forget obsolete/foreign-managed receipts, never unclaim foreign claims; 4) operator stats and read-only audit with explicit reconciliation command; 5) tests/CI.

Acceptance: original `BaseProtectionPolicy.contains` semantics across chunk boundaries (including negative coords and radius 0..3); all original Java invariants plus 203 new checks; secure ownership and idempotence; no broad Warium mixins or drop mutations; real-world MSPT benchmark required later.
