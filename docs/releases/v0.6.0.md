# v0.6.0 — Core Integrity Recovery and Visible Create Through-Shaft

**Status:** SOURCE CANDIDATE. The previous v0.5.4 JAR compiled and was tested in-game. This v0.6.0 patch has NOT been NeoForge-compiled or tested with Warium nukes. The independent core policy suite passes; Create model and world mutation adapter require a real build and multiplayer acceptance.

## Base reference
`feat/v0.5.4-update` commit `b447cd43` (do not apply to v0.5.3). Java 21, NeoForge 21.1.249, Create 6.0.10.

## Implemented
- Exposed Create shaft bore and two ring collars in the industrial block model, using the existing Create `CoreShaftRenderer` to spin the actual shaft, not merely an animated texture. This SHOULD show the mechanical connection through the housing on X/Z alignment; requires in-game test, especially different directions.
- Preserve the full v0.5.4 ownership, 27-slot inventory, FE, upgrades, FTB claims, raid rules and SaveData schemas (adds optional `CoreAxis` string to protection record, default X on older worlds and automatically backfilled while an older physical core remains loaded).
- Server-only physical integrity check every 20 ticks on registered teams. Never force load absent chunks. If registered PLACED block has been changed to air by a mod outside normal Break/Explosion hooks, reconstruct only at EXACT saved position and only if air and original PLACED record exists. Does not award points or create additional bearer items.
- If location is occupied by another block (or restoration fails), move registered core into ESCROW and release only tracked TeamWars-auto-created FTB chunks; manual claims must remain untouched. Reconciliation retries stale auto-claim releases for non-placed cores.
- New OP command `/teamwars admin coreaudit`, performs same integrity check and summarizes core/escrow/pending cleanup counts, without leaking coordinates to ordinary players.
- Reconcile checks physical block before creating new automatic claims in loaded chunks, to avoid recreating ghost claims for a removed core.

## Security and limits
- **NOT a universal nuclear shield.** Mods that bypass NeoForge explosion events can destroy other blocks inside claims regardless of the native CoreGuard. TeamWars can verify and repair a missing *core*, but cannot roll back terrain or prevent every third-party direct world edit.
- Reconstructs registered cores only into AIR; NEVER overwrites another block, a claimed foreign asset or terrain and NEVER loads a chunk to perform repair. Other mutations go to ESCROW. A legitimate normal pack updates ledger on the same server tick and is not recreated.
- FTB claims only released where our saved bookkeeping has the chunk AND FTB confirms the same owner's UUID. If the FTB team no longer exists, the reflection bridge may be unable to release: records are retained, OP needs manual FTB cleanup after backup; no unauthorized unclaim of anyone else's land.
- No additional teleport/reissue; Recovery retains inventory and upgrades. No general raid permissions or nuclear base damage enabled.
- Xaero's team exploration/markers from old v0.6 roadmap remain unimplemented. Revealing other users' personal map data or writing to Xaero caches without true revocation and two-client compatibility testing would be unsafe. Deferring this subsystem intentionally.

## Recovery after an existing Warium nuclear test
1. Back up world and FTB Teams/FTB Chunks saves together.
2. Load this version on disposable copy; run `/teamwars admin coreaudit` while target chunk is loaded.
3. If location is AIR, Core may be reconstructed and auto-claims remain because there is a real core again.
4. If occupied, mode changes to ESCROW and TeamWars-managed claims are released best-effort. Then `/teamwars base recover`, move to safe terrain, place; manual claims remain.
5. If pending auto-claim count stays nonzero, inspect FTB Team state and manual FTB admin claim tooling; do not delete FTB storage files blindly.
