# Rogler TeamWars v0.5.2 — industrial kinetic Base Core + onboarding

**Release status:** source candidate; Java 21 pure-policy suite verified locally. Create 6.0.10 NeoForge compilation and dedicated-server/client runtime tests **NOT YET VERIFIED**. No raid/claims privacy claims changed. Worlds must be backed up before first launch (Core BlockEntity migration).

## The actual implementation

- **Industrial 3D Base Core**: replaces the `minecraft:respawn_anchor_side0` cube model with original 32×32 industrial panel textures, warning/metal/copper faces and assembled multi-element casing; model leaves real shaft access on the horizontal X/Z axis. Legacy Y axis is supported with an alternate model. Block registry name `roglerteamwars:base_core` and unique server-authorized token are unchanged.
- **Native Create 6.0.10 shaft** (new required dependency): the core now uses Create `RotatedPillarKineticBlock`, `GeneratingKineticBlockEntity` and a Create shaft renderer. Before upgrade it generates 0 RPM. After upgrade it supplies **16 RPM at 16 SU per RPM = 256 SU** through two opposite faces on its horizontal axis. Create network registration is performed at common setup; exact Create/Flywheel/Ponder/Registrate Maven coordinates taken from official Create 6.0.10 docs. The output is intended for a few early machines; the user is reminded to build other stress production soon.
- **One survival purchase**: `/teamwars base upgrade create` costs 16 Create Andesite Alloy + 8 Create Shafts, requires owning team, loaded placed core within 8 blocks, no active raid. The paid `createLevel` persists in team infrastructure SavedData, transfers only under authorized orphan adoption, survives packing, relocation, escrow, defeat and restart. It never appears in transferable item NBT.
- **Clicking fixed**: sneak-right-click **empty main hand** packs the core. Sneak with held item allows normal Minecraft/NeoForge item use, for instance Crafts & Additions wire connectors, while protected enemy interactions still go through CoreGuard. `/teamwars base pack` remains as an explicit backup.
- **Guides / Starter Hub**: right-click core holding a vanilla `minecraft:book`, or `/teamwars guide`. `/teamwars guide books` discovers actual handbook item IDs installed at runtime, `/teamwars guide give <modid>` gives a recognized guide near the player's OWN placed core, if not already in their inventory. The scanner is intentionally conservative and does **NOT** promise every mod's manual is discoverable. For nonbook systems, players are instructed about Create Ponder (hover relevant item + W), AE2 in-game guide (hover item + W, GUI help button), FE adjacency and mechanical shaft connection. No fake Create or AE2 book is generated.
- **FE as before**: automatic FE push to six adjacent FE consumers/cables, 20/40/80 FE/t generation, 20,000 FE buffer, total push budget 160 FE/t. AE2 Energy Acceptor can be placed adjacent directly; no wire connector required. AE2 native ME controller/terminal/drive and Sophisticated upgrades are **NOT** implemented. Inventory cannot be automatically extracted by untrusted external mods.

## New dependencies and upgraded baseline

MC 1.21.1, NeoForge 21.1.249, FTB Teams 2101.1.11, FTB Chunks 2101.1.22, compatible FTB Library, **Create 6.0.10** now mandatory (user's Oct-12 pack already contains `create-1.21.1-6.0.10.jar`). Create transitively requires runtime libraries including Ponder and Flywheel as normally shipped. Maven development pins: `create_version=6.0.10-280`, `ponder_version=1.0.82`, `flywheel_version=1.0.6`, `registrate_version=MC1.21-1.3.0+67`. Check Gradle CI before deployment; modded dependencies may expose incompatible versions.
