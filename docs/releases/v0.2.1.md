# Rogler TeamWars v0.2.1 — core rescue hotfix

**Status:** source candidate, 106 offline Java checks passed. **NeoForge compile and two-player Minecraft runtime unverified until GitHub Actions and in-game test.** Supersedes v0.2.0 JAR (do not load both).

## Changes
- Worldspawn radius: default 0–5000 blocks, Overworld only; `carry_seconds=3600` unchanged. A still-default-generated v0.2.0 `roglerteamwars-base.properties` is migrated on startup with `.v020.bak` backup; edited/custom configs are not modified.
- More precise placement denials, actionbar `OUTSIDE ALLOWED BASE ZONE`; distinction between too close and too far (for custom nonzero min radius).
- Authentic dropped Base Core: checks lava/fire/cactus/void-near-bottom/despawn during item-entity ticking, makes item entity immune to ordinary damage, attempts a real-player BlockItem placement nearby using normal NeoForge permission checks, and otherwise transitions to recoverable ESCROW. When the token has already been spent/revoked, dropped duplicates are discarded. No duplicate live cores.
- Expiry and destroyed-item hooks for additional recovery opportunities. True arbitrary mod deletion of an item in an inventory/container **cannot** be detected generically; use explicit operator intervention. No forced world writes into protected claims.
- `/teamwars base recover` (same team, core in ESCROW, free slot): recovers without admin help, invalidates old token.
- `/teamwars admin reclaimlost <player>` (OP2) for already-lost *ISSUED* v0.2.0 items: forcibly invalidate prior token and move to ESCROW, then player runs `/teamwars base recover`. **Only run after confirming no other teammate still possesses a valid core.** `reclaimlost` intentionally cannot reset a placed core.
- New tests: 42 BaseCoreLedger assertions vs 25 prior; full 106 assertions.

## Dependencies (server AND clients)
- Minecraft 1.21.1, NeoForge 21.1.249.
- FTB Teams 2101.1.11, FTB Library matching your FTB Teams install (diagnosis FTB Library 2101.1.37).
- Rogler TeamWars v0.2.1 instead of 0.2.0.
- **No new third-party mods.** FTB Chunks, Xaero, Chunky, Sable, Sophisticated Core are present but NOT required by v0.2.1.

Test lava where placement cannot safely occur: ESCROW + `/teamwars base recover` delivers replacement and invalidates old token.
5. Upgrade old v0.2.0 test world with item already burned: run `/teamwars admin reclaimlost <player>`; player then `/teamwars base recover`; verify old token is unusable. Never reset entire SavedData without backup.
6. Set `carry_seconds=60` in a separate disposable world, restart and test 1h countdown equivalent; genuine timeout transitions to auto-place or escrow; restart/relog; no duplicates.
7. Multiplayer: two FTB parties, enemy must not place or recover another team's core. Test restart persistence and creative/survival; investigate other mod interference.

## Limits / risks
- Drop rescue auto-places **only** with an online teammate within 16 blocks and a dry supported valid location; it uses a real player for claim/NeoForge events. Else ESCROW; item isn't lost. Does NOT automatically teleport core across dimension/claims. Claim integration/grace, Chunkloader quota, Xaero border/rendering, mobile Sable bases, base movement, raids still pending.
- Full mod compilation not possible in the author's offline container. Verify in CI; do not declare stable from standalone core checks.
- The existing GitHub Actions monitoring script `scripts/watch-actions.ps1` runs after push. No new monitor is added here; keep the independent tooling commit already on the feature branch.
