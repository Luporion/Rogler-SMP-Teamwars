# Rogler Core v0.6.1 — safe-start Warium FusionBlast recovery

**Base:** Rogler TeamWars v0.6.0, GitHub commit `a10c7d4e`. **Source milestone, not runtime-certified.**

## Included

- User-facing branding **Rogler Core**; Gradle JAR is `roglercore-0.6.1.jar` and mod display name is Rogler Core. `/rogler` is a redirect to the full `/teamwars` command tree; original `/teamwars` commands remain intact.
- **NO migration** of `@Mod("roglerteamwars")`, registry/ResourceLocation IDs, packages, FTB team UUIDs, old SavedData keys, resource namespaces, world/serverconfig files, or game mechanics. Never install both `roglerteamwars-*.jar` and `roglercore-*.jar` in the same pack.
- Before world/entity loading, creates/reads `serverconfig/roglercore-compat.properties` with recovery OFF by default. Invalid config forces OFF and logs a warning.
- Optional Warium FusionBlast EntityJoin guard (NeoForge 1.21.1 `EntityJoinLevelEvent`). **Never requests chunks, accesses block states, entities, loot, or the region filesystem in this handler.**
- Target detection uses both the **observed** Java entity class simple name `FusionBlastEntityEntity` (from crash stack) **and** the installed-mod entity registry namespace `wariumce`; actual registry ID is discovered from the entity at runtime, not hard-coded. Optional `warium_fusionblast_entity_id` enforces an exact registered ID as an extra gate. No Warium classes are linked into Rogler Core.
- Recovery modes: `OFF` (no logging/blocking), `LOG_ONLY` (diagnostic sampling), `BLOCK_DISK_LOADED` (deny matching persisted entity joins; new matching entities are observed but allowed), `BLOCK_ALL_NEW` (deny new joins while disk-loaded entities are only observed). **`BLOCK_ALL_NEW` is NOT a complete server quarantine.**
- Operator (permission level 4) commands: `/rogler admin compat report`, `/rogler admin warium status`, `/rogler admin warium list`, `/rogler admin warium candidates`, `/rogler admin warium reload`. Logs include UUID, runtime type, dimension, position, disk flag, decision, bounded counter and a rolling list of 20 entries; no stored Java Entity or Level objects.
- The update script understands both `Rogler-TeamWars-v...-update.patch` and `Rogler-Core-v...-update.patch`, and now outputs `Rogler-Core-v0.6.1-full-source-exact.zip` from the user's true Git repository after applying the patch.
- Offline Java recovery policy unit tests added without Minecraft imports. Baseline runtime features (FTB CoreGuard, Create starter engine, FE, inventories, raids opt-in) unchanged.

## Important limitations

- **Actual WariumCE 1.0.3/1.0.4 JAR registry and the real crash-save entity** have not been observed in this build environment. A test must confirm that `FusionBlastEntityEntity` and namespace `wariumce` match the target type. Check `detected_id` in the status command after a matching join. Do not claim that the saved crash-loop is fixed until it starts several times in a **copy**.
- A canceled EntityJoin prevents the entity from being added to the world in this pass; **it does not guarantee permanent deletion from disk or recovery of a malformed `.mca` file**, nor does it undo damage already written to chunks or stop nukes which have already started ticking. We do not call `discard`, mutate Anvil region files, remove unrelated Warium entities, or change weapon balance by default.
- No performance fix for `BaseGuardService.onExplosion()`'s O(blocks x core count) loop yet. P0 follow-up v0.6.2 will add protected chunk index, benchmark and Warium/FTB lifecycle coverage.
- No new Create, Xaero, AE2 ME-drive, Sable, Mahou or Aether integrations are implemented in v0.6.1.
- Compiling this release against NeoForge/Create, user Minecraft gameplay, and the Warium crash-save startup remain unverified until GitHub Actions and on-server tests.

## Runtime prerequisites

**Required:** Minecraft 1.21.1, NeoForge 21.1.249, Create 6.0.10, FTB Teams 2101.1.11, FTB Chunks 2101.1.22. Keep existing modpack FTB Library and Create dependencies. **Optional:** Warium CE 1.0.3 or 1.0.4 for opt-in crash loop diagnostics/recovery. There is no new mandatory dependency in v0.6.1.

## One-time patch name transition

The **v0.6.0** `PATCH.cmd` (which runs before its own replacement is installed) only recognizes patch filenames matching `Rogler-TeamWars-v...-update.patch` for automatic branch creation and version checks. Therefore the **v0.6.1 patch deliberately retains its old-prefix transitional filename** `Rogler-TeamWars-v0.6.1-update.patch`. After applying it, the included update script supports `Rogler-Core-v...-update.patch` for all future releases. The first run may still produce `Rogler-TeamWars-v0.6.1-full-source-exact.zip`; its *content* is already Rogler Core and the next version's helper will use the new filename. The provided offline archive is named `Rogler-Core-v0.6.1-full-source.zip`.

## Safety and operations

1. Back up the complete test world (`world/`, `world/entities`, `world/data`, relevant FTB/team files), old JAR and serverconfig before using recovery. Test only on a fresh, **offline** copy with known original checksums.
2. Prepare the config **BEFORE starting Minecraft**. For a stuck persisted entity set `warium_fusionblast_recovery=BLOCK_DISK_LOADED`. Keep `warium_fusionblast_entity_id=` empty unless an exact `wariumce:...` registry ID was independently confirmed. No other Warium entity will be affected by this classifier.
3. Start the server and check console for WARIUM_FUSIONBLAST log lines, then `/rogler admin warium status` and `/rogler admin warium list` and `/rogler admin warium candidates` (or server console `rogler admin warium status`). If blocked count is zero while the server still crashes, the class/namespace or entity-join timing did not match; do not assume safety.
4. Run 2-3 controlled stop/restarts in the same **world copy**; verify that no new watchdog occurs, ordinary Warium items and non-target entities still work, base cores and FTB claims persist; never disable watchdog (`max-tick-time=-1`) to hide crashes.
5. Restore the mode `OFF` for normal operation until compatibility was independently verified. Recovery does not repair bad region sector tables; inspect such files read-only with an independent Anvil parser.

## Evidence and reproducibility

Source details based on user-provided Handover 2026-10-15 and the real 0.6.0 Java code. In the Handover, Watchdog 1 ~02:30 and Watchdog 2 ~03:33 have Warium `FusionBlastEntityEntity.tick -> FusionBlastTickProcedure -> Level.explode -> finalizeExplosion`, with Aether/C2ME as downstream participants; root attribution to Warium alone is **not proven**. The second crash shows the Rogler `BaseGuardService.owner/onExplosion` handler, which is a separate optimizable contributor.
