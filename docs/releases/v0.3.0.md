# TeamWars v0.3.0 – Protected bases and v0.2.2 stability repairs

STATUS: **SOURCE CANDIDATE**. Offline Java tests passed. NeoForge compile on GitHub Actions and two-client runtime are NOT yet verified.

## Implemented
- CoreGuard: 3×3 chunks centred on a PLACED core by default; Overworld only.
- Enemy block breaking, block placement, right-click interaction cancelled in guarded area. Unknown actors blocked from placing. No automatic permission for allied but non-team players.
- Native explosion-affected block list filtered within CoreGuard. No destructive raiding allowed in this version.
- 24-hour first-base Grace on a new team (persisted in Overworld SavedData; not refreshed by relocation or ordinary recovery); PvP damage from an attacking player is blocked within defended region during Grace.
- FTB Chunks 2101.1.x opt-in reflection integration (FTB mod **required to install**, adapter remains safe if FTB APIs are unavailable). Can claim up to 3×3 after admin opt-in, tracks chunks actually created by TeamWars, attempts to unclaim ONLY those chunks on pack.
- `/teamwars base protection`, OP `/teamwars admin syncclaims <player>` and `/teamwars admin grace <player> <minutes>`.
- Base Core placement refuses overlap with another PLACED core's guarded area.
- Creative mode: successful placement forcibly consumes the unique issued core item server-side.
- ESCROW recovery preserves carry time; an expired core is given only a final 1-second placement window, not a renewed hour.
- Core rescue now logs explicit `CORE_RESCUE` and out-of-zone state; existing `/teamwars base recover` / `reclaimlost` remain usable.
- `PATCH.cmd`, `VERIFY.cmd`, Downloads lookup (also redirected Windows Downloads), core tests then git push and auto CI watcher.

## Critical FTB visibility caveat
The uploaded 2026-10-12 DEV config has `def_claim_visibility: "public"`. Publishing automatic FTB claims would expose hidden base positions. For this reason `auto_ftb_claims` defaults to **false**. Before opting in: change the FTB Chunks team property defaults and any pre-existing team-specific claim visibility to `private` and verify as two enemy accounts. CoreGuard protection remains active independently.

## Explicitly NOT implemented
- Guaranteed defense against every modded world-edit method, piston/robot/contraption, cross-chunk interaction, special explosions or Sable physics. FTB claims and our native hooks are defense-in-depth, not a proof of universal protection.
- Automatic FTB Chunkloader quota split, Grace on new individual player join, full global initial Grace, automatic core destruction/raid point awards, attack windows, scoreboard, Xaero team map, Sable mobile nuke, market, base inventory and other long-term upgrades.
- Grace end does NOT remove normal enemy edit restrictions. Raids remain disabled even after Grace expires. `raids_enabled=true` is rejected to avoid accidental griefing.

## Config / commands
World file: `<world>/serverconfig/roglerteamwars-protection.properties`
```
claim_radius_chunks=1
new_team_grace_hours=24
auto_ftb_claims=false
base_guard_enabled=true
raids_enabled=false
```

Commands:
- `/teamwars base protection` – own team grace and recorded FTB claims (no enemy position leakage).
- `/teamwars admin syncclaims <player>` – retry partial FTB claim setup for the player's team.
- `/teamwars admin grace <player> <minutes>` – explicitly set Grace timer.
- `/teamwars admin reload` – reload **protection** config and the pre-existing team settings, but not Base Core radius/carry policy (restart required for those).

## Known failure modes
- FTB Chunks APIs may differ at runtime from upstream source; `syncclaims` reports reasons and CoreGuard keeps protection. A 2-client in-game test is REQUIRED.
- If the FTB adapter fails partway, some claims can remain after pack. Do not unclaim unrelated/manual claims; inspect log and claims GUI, use FTB admin tools only after backup.
- If a world was last saved with a different BaseCore radius, avoid changing it under existing PLACED records until migration tested.

## Rollback
Stop server; restore full world backup (including `data/roglerteamwars_basecores.dat`, `data/roglerteamwars_protection.dat` and FTB claim data), restore previous JAR and config. DO NOT simply remove v0.3 while leaving v0.3-generated claims without verification.
