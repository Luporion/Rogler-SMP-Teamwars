# Rogler TeamWars v0.5.3 — Native Base Core Dashboard

**Status:** source candidate; 252 Java policy assertions passed locally. NeoForge/GUI compile and real Minecraft runtime **NOT YET VERIFIED**. Base SHA `367ccdc2` (v0.5.2 hotfix). No Minecraft runtime screenshots are claimed for this release.

## Delivered

- Replace generic 9x1 chest-only menu with **TeamWars Core Dashboard**, a native `AbstractContainerMenu` + `AbstractContainerScreen` pairing.
- Always-visible persistent 9-slot TEAM inventory and 36-slot player inventory, no client-owned item state.
- Five tabs: status (protection, Grace, FE, raid), upgrades (server-authoritative purchases + explicit cost), power (FE generation/buffer and neighboring FE receivers / AE2 acceptor count), guides (Create Ponder, AE2 and found real books), future (clearly disabled modules).
- A player near their own placed core can open dashboard with right-click, `/teamwars base menu`, or `/teamwars guide`. Legacy CLI upgrades continue to work.
- Server receives only a restricted action ID via vanilla `clickMenuButton`. It **rechecks** `CoreInventory.stillValid` (membership, placed/loaded core, 8-block proximity), valid action, spectator/Creative/raid state; `CoreUpgradeService` re-checks actual resources and levels and consumes items. No client-provided team UUID, location, prices, materials, or FE balance.
- Purchases from GUI are quiet in chat; result is fed back into the menu's synchronized data. CLI retains its direct feedback. Book granting still prints one short confirmation (or error), no bulk book list.
- The FE status tests six neighboring `IEnergyStorage.canReceive` capabilities and detects adjacent `ae2:energy_acceptor` / `ae2:energy_cell` **by registry block ID**. The latter does **not** prove AE2 can receive power; use FE receiver count and actual stored power on the AE2 side.
- Core FE block capability remains **extract-only** and passive push to adjacent consumers continues (v0.5.1 behavior). No ME grid node, Drive, or integrated terminal is invented. Create generator remains v0.5.2 16 RPM / 256 SU when purchased.

## Non-goals / future hooks

Design reserves modules for Sophisticated upgrades, safe team AE2 ME terminal / ME Drive, bounded chunk loader with separate quota, Create expansions, radar, plants/growth, Xaero team map with revocation, voice, market and events. These are NOT active / purchasable in v0.5.3.

## Security / world compatibility

- Never trust client button IDs or inventory status. The server menu binds to the original team and closes on membership/core change (via `stillValid`).
- No changes to SavedData keys, team UUID ownership, world block ID, Create BlockEntity type, protected area, FTB claims, raiding or item serialization. Old v0.5.2 worlds should remain readable; test on a backup.
- Caution: old v0.5.2 `CoreGuideService` auto-detection of third-party manuals is heuristic; only registered items can be issued, but Patchouli setup for some books may still be missing.
- AE2 direct FE adjacency is existing functionality, not a new AE2 grid integration. An external Energy Acceptor connected to a ME cable network is required.

## Acceptance gate

1. GitHub NeoForge 21.1.249 / Create 6.0.10 compile must succeed; 252 pure Java checks alone **do not verify GUI API compatibility**.
2. On a backed-up world, right-click core: GUI opens. Shift+empty hand still packs; Shift+connector item does not pack.
3. Open inventory and move items, close/reopen, relocate core, restart: no item loss, ownership bypass or duplicate.
4. Survival player buys armor/FE/Create with exact inventory items; no phantom deduction; server denies Creative, raids and remote / foreign-player actions. GUI cost and result lines correctly update.
5. FE generator status and receiver count update after cable/AE2 Energy Acceptor placement, power actually transfers. Unconnected AE2 block only shows detection; it may not accept FE without the required capability.
6. Check 2-client UI/privacy; Raid, FTB claims and FTB team identities continue to work. Keep raids disabled until separate multiplayer acceptance.
7. Windows PowerShell `PATCH.cmd` produces an exact full tracked Git ZIP under Downloads; read test plan.
