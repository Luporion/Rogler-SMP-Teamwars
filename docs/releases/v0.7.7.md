# Rogler Core v0.7.7 – Sicherer privater Waypoint-Abgleich

**Status: Quellcode-Testversion.** Basis: v0.7.6 inklusive Registrate-CI-Bootstrap und bereinigten Dokumenten. Vor Einsatz müssen NeoForge Actions und DEV-Multiplayer-Tests erfolgreich sein. Netzwerkprotokoll **3** unverändert, keine SavedData-Migration und keine neuen Pflichtmods.

## Neue Funktionen

1. `/roglerwaypoints preview`: **Nur lesen**, beide privaten Waypoint-Listen der aktuellen Dimension vergleichen. Zeigt identische Positionen, Namens-/Farbabweichungen, wahrscheinliche Verschiebungen/Löschungen, Mehrdeutigkeiten und nur in einer Mod vorhandene Positionen. Ein Button **Konflikte prüfen** im `/roglerhud`-Wegpunktmenü zeigt die Zusammenfassung im Chat.
2. `/roglerwaypoints resolve ftb <index> <token>` beziehungsweise `resolve xaero <index> <token>`: übernimmt ausschließlich **Namen und Farbe** eines privaten Wegpunktes auf die andere Karte – und nur, wenn exakt **ein** Wegpunkt an denselben Koordinaten in derselben Dimension existiert. Der 16-stellige Token kommt ausschließlich aus einer unmittelbar zuvor ausgeführten Vorschau; ändert sich ein Eintrag, wird das Kommando abgelehnt. Es wird nichts verschoben oder gelöscht. Farbumrechnung ist wegen Xaeros 21-Farben-Palette approximativ.
3. `/roglerwaypoints sync`: weiterhin manuell und nur private, fehlende Positionen; neu werden **wahrscheinliche Move-/Delete-Konflikte und doppelte Namen/Koordinaten übersprungen**, statt möglicherweise bewusst entfernte/verschobene Punkte wieder einzufügen.
4. FTB: `getAllWaypoints()` wird jetzt anhand der echten `getDimension()`-Ressourcenschlüssel gefiltert, statt alle FTB-Punkte pauschal der aktuellen Dimension zuzuweisen. Das betrifft auch die optionalen `F`-Spiegelmarker.
5. Xaero: Farben werden korrekt über `WaypointColor.getHex()` gelesen, und FTB-RGB-Farben werden beim Import auf die nächstliegende Xaero-Palettenfarbe abgebildet. Bisherige 16-Farben-Modulo-Konvertierung entfällt.
6. Das Wegpunktmenü passt Seitenlängen an kleinere Bildschirmhöhen an.

## Sicherheitsgrenzen

- **Kein automatisches Umbenennen, Bearbeiten, Verschieben oder Löschen.** Der neue Metadaten-Abgleich braucht einen ausdrücklichen Befehl mit frischem Token.
- Kein automatisches Teilen privater Waypoints; Teamfreigaben/Widerruf aus v0.7.6 unverändert und weiterhin ausschließlich vom Server über aktuelle FTB-Teammitgliedschaft autorisiert.
- Keine Kopplung von Löschen/Move bei gleichen Namen, da die fremden lokalen Waypoint-APIs keine gemeinsame stabile Identität für beide Stores bereitstellen. Hierfür ist eine eigenständige versionierte Identitäts-/Tombstone-Schicht nötig.
- Kein Terrain-Cache-Sharing oder -Widerruf; keine Änderung an FTB Architectury-Pakettransport oder Standort-Radar.
- Persönliche Xaero-Wegpunktdateien **vor dem ersten Import** im Testprofil sichern. Die Persistenz `updateWaypoints()` und FTB-Persistenz müssen nach tatsächlichem Client-Neustart getestet werden.

## Bedienung

```text
/roglerwaypoints list
/roglerwaypoints preview
/roglerwaypoints sync
/roglerwaypoints resolve ftb <Index> <Token>
/roglerwaypoints resolve xaero <Index> <Token>
```

Die Vorschau gibt bei eindeutigen Namens-/Farbkonflikten genau die zulässigen `resolve`-Befehle aus. Für verschobene, mehrdeutige oder gelöschte Positionen gibt es absichtlich keinen Resolve-Befehl.

## Akzeptanztests

- Build: P0 + NeoForge CI grün, `registrate` aus SHA-geprüfter Quelle. Kein `EncoderException` beim Zwei-Client-Join.
- Konfig: private FTB-Standortsichtbarkeit, `long_range_tracker_interval: 0`, Xaero-Radar aus. Gegner, auch mit OP, sehen keine fremden Positionen/Team-Waypoints.
- Erstellung: FTB Overworld-Punkt und Nether-Punkt auf gleichem XYZ; Abgleich darf nur echte Dimension übernehmen. Keine `F`-Marker aus anderen Dimensionen.
- Konflikt: Ein Wegpunkt an gleichen XYZ mit anderem Namen/Farbe; `preview`, einmal `resolve`, veralteten Token ablehnen, erneut `preview` prüfen. Farb-Palettenrundung berücksichtigen.
- Löschen/Verschieben: Wegpunkt an anderer Position mit gleichem Namen darf nicht durch `sync` als Dublette re-importiert werden; keine fremden Wegpunkte löschen.
- Mehrdeutigkeiten: Doppelte Einträge an gleichen Koordinaten führen nicht zu einer automatischen Entscheidung.
- GUI: `/roglerhud`, Konfliktvorschau und Seitenwechsel bei unterschiedlichen Auflösungen; 2-Team-Test mit Teamwechsel, Widerruf, Welt-/Clientneustart.
