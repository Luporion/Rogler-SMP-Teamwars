# Rogler TeamWars v0.5.1 – Core Inventory, FE and Integration Preparation

**Status: SOURCE CANDIDATE.** No actual NeoForge 21.1.249 CI build or in-game verification performed in this authoring environment. No new third-party required mods. The user's v0.5.0 patch was delivered but not tested before this update.

## Verified source requirements

Earlier user decisions: (a) 9-slot core inventory, later selectable Sophisticated Core upgrades; (b) early and *limited* FE generation, example 20 FE/t initially and 80 FE/t upgraded; (c) tiny Create kinetic/stress source (example 256 SU at 16 RPM); (d) AE2 connectivity including terminals and ME Drive eventually; (e) early accessible costs, world/admin-configurable tuning, no free endgame plant. These were **design wishes**, not features already implemented. Roadmap also includes crop boosts, radar and bounded per-core chunkloading, all **out of scope** for this slice.

## Implemented in v0.5.1 source

- New team-keyed `roglerteamwars_infrastructure.dat` Overworld SavedData. **Exactly nine inventory slots**: right-click your own PLACED base core to open a vanilla nine-slot chest screen; sneak-right-click still packs the core. Foreign teams and players without a valid party cannot open it. The shared server-side container checks FTB party UUID, registered physical block, dimension and <=8 block distance on ongoing menu interactions. Inventory changes mark SavedData dirty.
- The inventory is **owned by the team**, not the physical block. Packing, re-placement, ESCROW, raid defeat and recovery do not silently drop or duplicate the stored items. Explicit admin orphan adoption carries it over only when the destination has no stored data; never by matching team name. Items remain locked while core is not placed. Full-world backup required before downgrade.
- Passive **Forge Energy generation** only while registered core is PLACED, block loaded and in the Overworld. Default FE/t: tier 0=20, tier 1=40, tier 2=80. Dedicated `<world>/serverconfig/roglerteamwars-core-power.properties` supports `base_fe_per_tick`, `tier1_fe_per_tick`, `tier2_fe_per_tick`, with validated `0 <= base <= tier1 <= tier2 <= 256`. Reload using `/teamwars admin reload` or restart.
- Team-owned FE storage capped at **20,000 FE**. NeoForge `Capabilities.EnergyStorage.BLOCK` exposes extraction but not external insertion. Source pushes to adjacent FE receivers (max combined **160 FE/t**, no chunk force-load) and supports pulling from neighboring compatible machinery. Energy remains team-persistent through pack and recovery; generation stops while packed or unloaded.
- New material-purchased energy upgrade: `/teamwars base upgrade energy`, usable in Survival within 8 blocks of placed core, not during a raid. Tier 1 costs 16 redstone + 8 iron ingots. Tier 2 costs 32 redstone + 8 gold ingots. `/teamwars base energy` shows stored buffer and actual configured rate. `/teamwars base upgrade status` also shows energy tier. Existing armor upgrades and combat behavior unchanged.
- Vanilla-style UI is reuse of standard container screen, no custom client packet/screen. FE-capability query is safe if no third-party mod is installed; new mandatory deps **none**.
- A generic bounded `CoreIntegrationPolicy` records proposed tiny Create output: 256 SU @16 RPM initially, optional 512 SU upgraded. This is **a contract only**, NOT a working kinetic source.

## Partial AE2 functionality

Energy transfer to a neighboring AE2 **Energy Acceptor** via ordinary FE is the only presently implemented AE2-compatible behavior. Official AE2 docs say the Acceptor converts **2 FE = 1 AE**; an actual AE2 runtime check is still required. No `IGridNode`, ME drive bay, ME Terminal, ME Storage Bus access or integration of base items into AE2 inventory yet.

## Explicit NOT implemented / safety guardrails

- **Create rotational source / SU is NOT implemented.** Requires Create KineticBlockEntity / GeneratingKineticBlockEntity registration with exact installed Create/NeoForge ABI and dedicated performance tests. No Create stress added to network by this version.
- **AE2 true ME network node / embedded terminal / ME Drive NOT implemented.** Do not represent FE compatibility as a true AE2 terminal.
- **Sophisticated Core upgrade handler NOT implemented.** Normal 9-slot inventory is available; expansion/selected upgrades require version-pinned adapter and attention to serialization on pack and raid defeat.
- **No public ItemHandler capability** for private contents. Standard `IItemHandler` offers no requesting player's team identity; exposing it indiscriminately could let hostile Create/AE2 automation extract items even where manual edits are blocked. Solve caller authorization before enabling any external extraction.
- No passive energy generation while unloaded, no automatic chunkloading, no infinite energy, no unbounded tick acceleration.
- FTB claims PRIVATE is NOT packet-level coordinate confidentiality in FTB Chunks 2101.1.22; v0.5.0 privacy guard stays. Raids remain disabled unless OP opts in and tests.

## Rollback

Always back up the **entire world including FTB files, raids, core/protection and new `data/roglerteamwars_infrastructure.dat`**. Downgrading the JAR while keeping v0.5.1 data may make the 9 slots and FE state unavailable. Safest rollback restores the prior world backup and prior v0.5.0 JAR together.
