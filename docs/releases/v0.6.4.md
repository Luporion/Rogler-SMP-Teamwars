# Rogler Core v0.6.4 — Sable 2.0.6 removed-sublevel preflight (WITHOUT Destructive)

**Status: source candidate.** Offline policy tests passed. A NeoForge 21.1.249 build and real Sable 2.0.6 + Shtreimel integration test are still REQUIRED. Do not advertise the crash as fully fixed until the actual failing scenario and its persistence are verified.

Based on v0.6.3 `c2250f90`, preserving all existing world/registry IDs, FTB claims, base/FE/Create and Warium recovery features. Sable `sub_level_splitting=true` remains **enabled**; Rogler Core does not write to `sable-common.toml`.

## Changed

- Optional NeoForge/Mixin preflight for **exactly Sable 2.0.6**, Sable: Destructive **absent**. No imported Sable classes, separate JAR, runtime or compile-time Sable hard dependency.
- At `SubLevelHeatMapManager.tick()` HEAD, reject heatmap tick if its owner already `isRemoved()`.
- At `SubLevelHeatMapManager.split()` HEAD **before any Sable split-state mutation**, check removed owner and the planned fragment anchors via the same `Sable.HELPER.getContaining(Level, Vec3i)` API used by upstream 2.0.6; abort only that split if containing sublevel is removed. Reproduces the original grouping, no-op whole-sublevel and retained-largest-group calculations. Grouping uses only one anchor/count per split index, not a copy of every block list.
- Per-world opt-out `serverconfig/roglercore-sable-lifecycle.properties`. Defaults: enabled only on known 2.0.6 without Destructive; all checks individually configurable. Invalid config => guard OFF with warning. Unknown Sable version => OFF. Destructive detected => OFF (let add-on own the protection).
- Bounded per-minute logs, `/rogler admin compat lifecycle`, existing `/rogler admin compat reload` also reloads this guard, existing compat report includes guard state.
- NeoForge mixin entry is optional, Sable target declared by string, `@Pseudo`, **no Sable class in common code**. Existing Sable diagnostics/claims/nuclear recovery remain intact.
- 22 additional pure-Java policy checks, on top of prior 536.

## Limitations / explicit NOs

- This is a **pre-mutation** guard. A separate Sable `SplitListener` may remove a parent **after** the preflight and before `assembleBlocks`. That reentrancy path is **not yet protected**, because intercepting then could leave cleared split indices and partially migrated data. Do not catch the exception and return `null` or silently discard fragments.
- Not verified against the binary `sable-neoforge-1.21.1-2.0.6.jar` or the installed `shtreimel-guard` bytecode: checked exact source tag `mc1.21.1-2.0.6-neoforge` only. Source/bytecode drift, mixin order, access and physics safety need real server QA.
- No fix claimed for `Body has been removed` during shutdown, Mahou oversized AABBs, Warium/Mianbao nuke tick spikes, or region file permissions.
- Does not read/write `world/entities/*.mca`, `world/sublevels` or Sable occupancy data, and never force-loads chunks or destroys blocks.
- Existing world data is unchanged. Never test nuclear stress on production.
