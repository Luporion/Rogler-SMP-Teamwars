# Rogler Core v0.8.6 – Ender Chest transport-timer hotfix

**Basis:** exact v0.8.5 source archive. **Release status:** local Java policy, integration structure, v0.8.3 C2ME safety and v0.8.5 UI regression checks passed; actual NeoForge compilation and dedicated-server runtime validation are still open.

## Observed defect

`BaseCoreService.oneSecond()` only advanced `carriedSeconds` while an authorized core item was found in the inventory of an **online FTB team member**. Moving the core into an Ender Chest, ordinary chest, automation inventory, or logging out stopped the one-hour countdown.

## Fix

- The **server-owned ledger** is the authority. Every `ISSUED` core is accounted, independent of item holder/container, dimension and connected players. `PLACED` and `ESCROW` entries do not consume additional transport time.
- A **versioned persistent wall-clock checkpoint**, keyed by team and the current bearer token, records the last accounted timestamp. The checkpoint survives save/restart and accounts elapsed wall time while the server was shut down. Subsecond remainder is preserved. A newly issued or rotated token starts a new checkpoint, while spent seconds remain in the ledger (a repack never resets the budget).
- `BaseCoreItem.place()` first reconciles elapsed wall time, before authorization; expired tokens cannot be placed immediately after reboot or pulled from an Ender Chest just ahead of the next server tick.
- At expiry, the core becomes `ESCROW` and its bearer token is no longer valid. The system **does not teleport items out of Ender Chests** or rewrite arbitrary third-party containers. A physically remaining old item is inert; the team must use the existing controlled recovery (`/teamwars base recover`). The valid carrier item is consumed on timeout when it is in an online teammate's inventory.
- Existing held-item automatic placement may still occur **before expiry**, only via the normal, permission-checked Minecraft placement path. No chunk force-load, direct `setBlock`, new duplicate item or bypass of FTB protections.

## Data compatibility / rollout

- `roglerteamwars_basecores.dat` increments its `Schema` marker from 1 to 2 and adds optional `TransportClocks` entries. Existing `Cores` records, item Team/Token tags, claims and FE data are unchanged.
- **Migration limit:** legacy v0.8.5 saves have no timestamp. We retain their already recorded `Elapsed` seconds, and start the new wall clock on the first observation. Previously paused time cannot be reconstructed from the save; do not fabricate a past timestamp.
- A fresh v0.8.6 save preserves the clock through subsequent server restarts; a snapshot that was already expired while the server was offline is reconciled when the server resumes, or immediately before a manual placement.
- Before live installation, back up the entire world and `serverconfig`; install the same mod JAR on server and clients. Do **not** downgrade a schema-2 world without restoring an appropriate backup.
