# Rogler Core v0.8.0 – Client-private Wegpunkt-Identitäten und kontrollierter Metadatenabgleich

**Stand 23. Oktober 2026: Quellcode-Testkandidat; kompletter NeoForge-Build und Multiplayer-Laufzeit v0.8.0 ausstehend.** Vorgänger v0.7.7 wurde am 23.10.2026 in GitHub Actions erfolgreich gebaut (NeoForge Run `39875853255`, P0 Core Run `39875853278`); sein In-Game-Test wurde nicht berichtet.

## Neu

- `/roglerwaypoints link <FTB-Index> <Xaero-Index>` verknüpft **genau zwei persönliche Wegpunkte** an derselben Koordinate in der aktiven Dimension. Mehrdeutige und bereits verknüpfte Positionen sind verboten. Die neue UUID gehört allein dem Rogler-Journal, nicht einem der beiden Kartenmods.
- `/roglerwaypoints changes` prüft die verknüpften Wegpunkte gegen beide zuvor gespeicherten Momentaufnahmen und zeigt eindeutige einseitige Metadatenänderungen, Konflikte, fehlende Punkte und Mehrdeutigkeiten. Reine Prüfung verändert keine Karten-Daten.
- `/roglerwaypoints apply <UUID> <Token>` übernimmt **ausschließlich Name und Farbe** von der einzigen geänderten Seite, und nur mit aktuellem Prüf-Token. Die tatsächlich gespeicherten Farben werden separat für FTB und Xaero im Journal vermerkt, weil Xaero eine Palette statt beliebigem RGB nutzt.
- `/roglerwaypoints acknowledge <UUID> <Token>` aktualisiert die Journal-Baseline erst, wenn der Benutzer beide Wegpunkte manuell auf dieselben Werte gebracht hat.
- `/roglerwaypoints unlink <UUID>` vergisst lediglich Roglers lokale Beziehung. Keiner der beiden echten Wegpunkte wird dadurch gelöscht.
- `/roglerwaypoints sync` überspringt Positionen, die im privaten Journal als verknüpft registriert sind. Löscht der Benutzer einen dieser Punkte, wird er deshalb **nicht automatisch aus dem anderen Store wiederhergestellt**. Dieser Schutz gilt über Client-Neustarts hinweg.
- Der Wegpunkt-Einstellungsbildschirm enthält zusätzlich den Button „Verknüpfte Wegpunkte prüfen“, der die Zustände im Chat anzeigt.

## Datenschutz und Datenablage

- Journal: `config/roglercore/private-waypoint-links/<SHA256-Kontext>.properties` im **Client-Profil**; der Hash basiert auf Server-/Einzelspieler-Kontext und lokaler Spieler-UUID. Keine Daten an den Rogler-Server, keine privaten Server-SavedData und kein automatischer Team-Upload.
- Geschrieben wird über eine temporäre Datei und eine ersetzende Umbenennung. Unlesbare oder nicht unterstützte Journalformate blockieren die private Synchronisierung, **anstatt Löschschutzregeln zu ignorieren**. Die Grenze beträgt 128 Paare pro Serverprofil; bestehende Welt-/Core-Daten bleiben unverändert.
- Alle Teamfreigaben von v0.7.6 bleiben **gesondert explizit**; v0.8.0 ändert weder Teamrechte noch das Rogler-Netzwerkprotokoll (`3`). Die Architectury-Paketkorrektur von v0.7.4 und die FTB-Positionsfilterung bleiben bestehen.

## Technische Grenzen

- Die Rogler-UUID ist **keine native Waypoint-UUID**. Da beide fremden APIs keine gemeinsam nachweisbare unveränderliche ID liefern, kann nach einem Verschieben oder Löschen nicht zuverlässig unterschieden werden, ob ein Eintrag absichtlich entfernt oder an anderer Stelle neu angelegt wurde. Solche Fälle werden **nur angezeigt**, nie automatisch verschoben, gelöscht oder wiederhergestellt.
- Nur eindeutig gepaarte Wegpunkte in der *aktuellen Dimension* können automatisch als einseitige Metadatenänderung erkannt werden; auch dann ist `/apply` ausdrücklich erforderlich. Keine Hintergrund-Auto-Synchronisierung und keine automatische Löschpropagation.
- Weil Xaero nur eine begrenzte Farbpalette hat, kann die Zielfarbe geringfügig vom FTB-RGB abweichen. Journal-Baselines speichern beide echten Farben separat.
- Vor Minecraft-Tests lokale Xaero-/FTB-Wegpunkte und Welt sichern. Keine neuen Pflichtmods, keine Server-Datenmigration, kein neues Netzwerkprotokoll. Die Client- und API-Integration muss trotz bestandener reiner Java-Tests mit NeoForge und euren Mod-JARs geprüft werden.
- **Native widerrufbare Xaero-Geländekacheln und Team-Sprachfunk sind nicht Bestandteil von v0.8.0.**

## Abnahme

1. Alle lokalen Java-Tests, neue Journal-/Link-Regeltests, `check-waypoint-link.py`, Registrate-Bootstrap und NeoForge-Build müssen grün sein.
2. Zwei Clients Team A, ein Client Team B (einschließlich OP) können joinen; Karten zeigen keinerlei Gegnerdaten oder ungewollte Freigaben.
3. Zwei persönliche Punkte am gleichen Ort per `/link` paaren; Neustart und `/changes` muss stabile Identität zeigen.
4. Nur FTB-Name ändern, `/changes` → `FTB_METADATA_CHANGED` und `/apply` bestätigt Name/Farbe in Xaero. Gegenrichtung wiederholen. Falscher/veralteter Token muss ablehnen.
5. Client-Dateien sichern, einen verknüpften FTB-Wegpunkt entfernen und `/sync` testen: nichts wird wiederhergestellt. `/changes` zeigt `MISSING_FTB`. `/unlink` entfernt nur Journal-Eintrag.
6. Ambiguität, zwei gleichzeitig verschiedene Änderungen, Dimensionwechsel und kaputte lokale Journaldatei testen: keine automatischen Schreibzugriffe.
7. Danach FTB/Xaero-Persistenz nach Client- und Serverneustart nachweisen.

**Ausgangsbranch:** `feat/v0.7.7-update`. Patch mit `PATCH.cmd` einmal anwenden; dann CI-Build. Ohne erfolgreichen Build und DEV-Abnahme **nicht auf den Produktivserver installieren**.
