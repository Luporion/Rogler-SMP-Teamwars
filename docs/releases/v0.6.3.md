# Rogler Core v0.6.3 — Sable safety compatibility assessment

**Status:** source candidate; v0.6.2 build `1321a76a` succeeded in GitHub Actions, but **v0.6.3 NeoForge CI and gameplay are untested** at authoring time. Run 1.21.1 / NeoForge 21.1.249 / Java 21 / Create 6.0.10.

## Actual, implemented scope

- New optional, **read-only** Sable compatibility adapter `SableCompatibilityService`. It reads the NeoForge loader's installed mods (real ID + version). Looks for `sable`, `sabledestructive`, Warium and known dependencies; display-name matching for unknown Mianbao, Aeronautics, Collision Damage, etc. is **diagnostic only**.
- Read-only bounded parse of the existing server `config/sable-common.toml`. Reports `sub_level_splitting`, optional `sub_level_splitting_heatmap_steps`, missing/ambiguous/invalid. **Never edits the file and never turns splitting off.** The path is resolved relative to the dedicated server process's working directory.
- Warns if Sable appears older than 2.0.3, Sable: Destructive older than 2.2.0 or missing, if splitting is not confirmed, or if potentially overlapping collision addons are found. Detection is not proof of mixin injection, API operation, or network stability.
- Admin Level 4 commands: `/rogler admin compat report` (Warium + Sable summary), `sable`, `mods`, `explosions`, `reload`. Legacy `/teamwars ...` remains an alias.
- Optional **observation-only** per-explosion counts (`explosion_observation_enabled=false` by default), capped to 16 dimension buckets. It counts the input list of NeoForge explosion affected positions, **not** sublevel blocks, server MSPT, time in Warium, or actual changes. Counters reset on restart/reload. No `getChunk`, `getBiome`, cross-dimension scanning or per-BlockPos walking in this observer. Existing 0.6.2 `explosionstats` measures the Rogler Core protection handler separately.
- Added 45 new offline assertions (22 policy + 9 splitting + 14 counter), so **536** assertions overall after passing existing 491.
- Preserves `roglerteamwars` *internal* mod ID and world/SavedData schema, all existing Core/FE/Create/FTB behavior, Warium OFF-by-default quarantine, and v0.6.2 explosion index.

## Deliberately NOT implemented

- No second Sable `SubLevelHeatMapManager.tick/split` mixin: Sable: Destructive 2.2.0's release notes already claim fixed removed-sublevel handling. Verify that version in a real server before claiming the crash is solved.
- No direct Mianbao/Warium -> `SableDestructiveApi` calls: the precise installed jar/bytecode and API descriptors were **not provided or verified**; do not invent methods or duplicate explosion/loot processing.
- No magical fix of malformed entity-region files, permissions, `Body has been removed`, Mahou giant AABBs, the Warium 60-second synchronous `Level.explode` stall, or guaranteed cross-plot CoreGuard permissions.
- No new external mod dependency, classloading of optional addon APIs, entity quarantine changes, intrusive world edits, or `/sable-dv` setting changes.

## Configuration

Optional `world/serverconfig/roglercore-sable.properties`:

```properties
# default is disabled; read-only counters, do not affect gameplay
explosion_observation_enabled=false
```

If absent, all observation counters remain disabled. If malformed/oversized, the safe fallback is OFF. Reload via `/rogler admin compat reload` (read-only; metrics counters reset). `config/sable-common.toml` is never modified.
