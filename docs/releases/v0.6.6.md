# Rogler Core v0.6.6 — FTB membership / Core Guard permission hotfix

## Evidence and symptom (2026-10-17)
- Dedicated server running Rogler Core 0.6.5 and FTB Teams 2101.1.11.
- Core auto-claims still exist (nine claims); the current symptom is members unable to break blocks near an already placed Core.
- Source and the supplied compiled 0.6.5 JAR both contain a policy bug: TeamAssignmentPolicy.assign() treated an oversized *real* FTB party as an invalid solo player. BaseGuardService.enemy() then denies all building rights, even for its owner. The default `max_team_members` is 4, independently of FTB Teams' real max party size.
- Logs alone do not establish that this specific team's size exceeded 4. In a future incident, compare `/rogler team`, `/rogler status` and the throttled CORE_GUARD_DENY line. Another possibility is that the player is in a different FTB party from the registered Core's canonical UUID.

## Fix
- FTB Teams remains the *sole* membership authority. A member UUID reported by a valid effective FTB party keeps that party UUID and all existing Core / protection rights irrespective of the advisory TeamWars size cap.
- Preserve strict rejection of null/solo FTB teams, nonmembers, missing FTB data and API errors. No admin or Creative bypass added.
- Oversized parties now retain the same scoreboard identity; emit a warning in `/rogler team`, `/rogler status` and synchronization status instead of quarantining actual members.
- Add rate-limited (once per minute per denied player) server-only `CORE_GUARD_DENY` diagnostics showing actor UUID, owner UUID, FTB party UUID, and policy reason. Does not print base coordinates.
- 0.6.6 version bump, no changes to persistent schemas, FTB teams data, claim records, Core tokens, mixins, or other mod dependencies.

## Verification
- Run `bash scripts/test-core.sh` or `VERIFY.cmd`; TeamAssignmentTests cover oversize owners, oversize members, nonmembers, identity continuity and warnings.
- NeoForge CI compile and 2-client dedicated integration tests required; pure Java tests cannot prove FTB or FTB Chunks runtime permissions.
- Start with a backup of world, FTB data, configurations and all `SavedData`.
- For a team with more than four members, confirm `/rogler team` gives the correct FTB UUID with a size warning and that breaking/placing works in the Core zone. An outsider must still be denied.
- Repeat with team of four or fewer, solo player, after kick/leave, after reconnect and restart, and with Core packed/placed.
- Verify FTB Chunks independently: its claim protection can still block editing when team permissions or claimed owner do not match.

## Temporary workaround for the specific oversized-team symptom on v0.6.5
- Run `/rogler team`; only when it reports `FTB party exceeds the configured member limit`, increase `max_team_members` in world/serverconfig/roglerteamwars.properties (resolve actual path in source before editing) to at least the true team size, then `/rogler admin reload`.
- Do not delete or reissue the Core, rename teams, or blindly unclaim chunks.
