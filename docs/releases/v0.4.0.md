# v0.4.0 — automatic private FTB claims + safe core-only raids

STATUS: **SOURCE CANDIDATE**; offline Java invariants passed. Real GitHub Actions NeoForge compile and 2-client gameplay unverified.

## Functional boundaries

1. Base core 3×3 region automatically creates missing TeamWars FTB claims when `auto_ftb_claims=true`; this is the default for freshly generated protection config, but previously created configurations are not silently rewritten. Existing manual team claims are not flagged as TeamWars-created and must survive pickup.
2. Before claiming, reflective FTB Teams 2101.1.11 property API sets `FTBChunksProperties.CLAIM_VISIBILITY` to `PrivacyMode.PRIVATE`, then re-reads it. If that fails, no new claims are created. Changes to visibility are synced to clients. Test opposing clients; do not declare secrecy from config alone.
3. Claim reconciliation after startup, config reload, every ~60 s, after core placement. Pack and raid victory release only TeamWars-owned tracked claims. CoreGuard protection is independent of claim API success.
4. `raids_enabled=false` by default; OP must explicitly enable in world protection config, reload, and open a specific defendant raid 1–30 minutes. A defender must be online and out of Grace. On quitting, raid ends within one second (or first hit is rejected).
5. 10 actual attacks on physically present core with cooldown 750ms, first attacking team locked. No creative/spectator attacks. Valid 10th hit removes the core, converts ledger PLACED -> ESCROW, releases TeamWars-created claims, grants new Grace, awards exactly one persistent point. Recovery uses `/teamwars base recover` and rotates token.
6. No other destruction is allowed during raids. TNT, Create machines, physics mods, Sable, etc. are NOT accepted as damage sources. Do not enable destructive sieges until special-modded protections are audited.

## Config and commands
`<world>/serverconfig/roglerteamwars-protection.properties`:
```
claim_radius_chunks=1
new_team_grace_hours=24
auto_ftb_claims=true
base_guard_enabled=true
raids_enabled=false
```
**For existing v0.3.x worlds:** old `auto_ftb_claims=false` remains false until deliberately changed to true; reload with `/teamwars admin reload` to backfill already placed cores. Team-specific properties will be switched to PRIVATE on sync. Restrict FTB claim-property edits if secrecy is critical.

Operator testing (throwaway world only):
```
/teamwars admin grace <Defender> 0
/teamwars admin reload
/teamwars admin raidstart <Defender> 10
/teamwars admin raidstop <Defender>
/teamwars war scores
/teamwars war status
```
First set `raids_enabled=true` for manual tests. Open only while the defender player is online. Normal players can inspect their own raid status and public war scores but never enemy core coordinates.

## Test before production
- Server starts v0.4.0 with exact FTB mods. Two parties A/B. Place core; verify automatic 3x3 claims even without OP `syncclaims`; view FTB map from enemy client. Confirm cannot locate A via claims, including existing-public team migrated to private.
- Pack/re-place core with manual claim present; only tracked claims disappear/reappear; check world restart. Then set `raids_enabled=true` and remove Grace via OP to test.
- Open raid B against A with A online, observe 10 hits by B, 1 point, A recovery/24h grace, logged `RAID_WIN`. Verify A cannot pack during raid. Repeat clicks, cooldown abuse, B leaves, A logs out mid raid, window expires. No dupes, points persist restart.
- During active raid, enemy cannot break other blocks, Tree Physics nor vanilla TNT can destroy guarded blocks; test separate Create/Sable grief only in disposable backup.
- Review `latest.log` for `FTB_CLAIM_PRIVACY`, `FTB_CLAIM_SYNC`, `RAID_OPEN`, `RAID_WIN`, `RAID_CLOSED` and reflection errors. Monitor MSPT/TPS.

## Rollback
Take **full world backup** before first launch, including FTB Teams/Chunks and saved data. Rolling back v0.4.0 JAR without restoring new `roglerteamwars_raids.dat` and core ledger/protection changes is NOT sufficient after successful raid victory.

## Known limitations
No CI runtime proof yet. Current implementation uses event-based core left-click rather than a custom network attack packet. Multiple mod event handlers may intercept it. The FTB reflection property setter and claim sync must be verified against the exact installed versions. Team privacy can be changed by authorized FTB UI interactions between periodic reconciliations; enforce team property editing policy on production.
