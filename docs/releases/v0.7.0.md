# Rogler Core v0.7.0 - privacy-first map foundation (TEST BUILD, not feature complete)

**CODE BASIS:** v0.6.6. The update patch is based on v0.6.5 and **includes** the v0.6.6 FTB membership fix, so the user can update directly from v0.6.5.
Minecraft 1.21.1, NeoForge 21.1.249; existing Core NBT remains untouched.

## Implemented

- Login-time documented Xaero fair-play server message disables normal Xaero entity radar; this is the **safe** default for competitive teams, but also disables cave mode and mob radar. Mini- and fullscreen maps, own position and personal waypoints remain usable.
- Packaged optional enforced Xaero server-profile templates, compatible with the layout observed in Rogler Alpha Oct-09 diagnostics. These also disable tracked-player overlays in both maps. **Do not overwrite existing profiles without a backup**; explicitly verify profile enforcement. An external tracking addon that sends enemy coordinates may bypass this profile; audit every waypoint/tracking addon.
- Read-only `TeamMapPrivacyPolicy`: never send a different FTB party's positions or Core position to another party. This policy is not yet wired to a Xaero custom client renderer.
- Server-side **personal** exploration provenance based on actual sampled movement (not Chunky pregen), dimension-aware, with bounded interpolation but not through teleports. Existing `ExplorationIndex` and `ExplorationStore` store UUID ownership per chunk. Fail closed if snapshot is corrupt, preserving the original data.
- ` /rogler map status `: number of personally visited chunks and union of the CURRENT FTB party. Currently **does not reveal those chunks in the actual Xaero client renderer**.
- ` /rogler map zone `: spawn-distance and allowed Core zone in Overworld.
- 20 new offline privacy/provenance tests plus prior v0.6.6 test suite; storage replacement attempts to preserve POSIX ownership/group/mode or Windows ACLs.

## NOT IMPLEMENTED YET (must not be promised)

- Reversible personal/team exploration in *Xaero's World Map and Minimap*. Xaero has independent client tile caches; without a verified client adapter revoking server visibility would still leave rendered world details on clients.
- Long-distance teammate markers. Server messages and map policy do not grant them. Default intentionally hides *all* Xaero player radar until we can validate a team-only client layer.
- Automatic two-way syncing of **all personal Xaero waypoints** to FTB Chunks' local waypoints. TeamPins 2.0.0 (NeoForge 1.21.1) can provide centrally managed shared team pins in Xaero; do not assume it syncs all personal waypoint edits in both directions. Verify that its client player-tracking feature only shows same-team players before enabling it.
- Client-side zone rings, border shaders, map overlay, or permanent HUD labels. Current release offers `/rogler map zone` command as an interim tool.
- Server-side NeoForge compile and dedicated-client map tests have **not** been run here. Pure Java tests are not proof of NeoForge API or Xaero compatibility.

## Security and configuration checklist before gameplay

1. **Back up your server, world and configs**. Stop the server.
2. Put the **NeoForge CI-built** `roglercore-0.7.0.jar` in `mods/`, removing the previous 0.6.x jar. This source ZIP is not a compiled Minecraft mod.
3. For stronger, persistent enforcement install server-side Xaero Minimap and World Map. Merge the two template `deployment/xaero/.../server_profiles/default.cfg` files into your own server files `config/xaero/.../server_profiles/default.cfg`. Preserve custom settings in backups. Ensure corresponding `common.cfg` has `default_enforced_profile = default` and the enforced profile permission is not bypassed.
4. Check `config/xaero/lib/common.cfg` has `everyone_tracks_everyone = false` (seen so in Oct-09 snapshot). **Never enable `everyone_tracks_everyone`**.
5. For FTB Chunks, set `def_claim_visibility: "private"` and `def_player_visibility: "private"` in `config/ftbchunks-world.snbt` if you want strict no-enemy overlays. Review *existing* team-specific visibility settings separately; defaults do not retroactively hide pre-existing public claims.
6. Check all clients have the same approved maps, radar integrations and security settings. Restrict unauthorized map/tracking addons via pack management; server privacy does not prevent a malicious external minimap mod from observing physically sent entity data.
7. In game `/rogler team`, `/rogler map status`, `/rogler map zone`. Test with two adversarial FTB parties, as well as when player A changes team.
8. Check `/rogler team` still authorizes an oversized party (v0.6.6 fix), and previous Core/FTB claims remain unchanged. Run existing Core/claim smoke tests.

## Waypoint integration architecture

**Preferred:** one Xaero minimap/fullscreen world map. Keep FTB Chunks for claims. Install [TeamPins](https://www.curseforge.com/minecraft/mc-mods/teampins-ftb-teams-map-integration) on both sides *after* security testing. It shares team-owned pins across Xaero and FTB integrations; it is **not** a verified lossless two-way conversion of every local Xaero/FTB waypoint. We do not auto-import personal waypoints (privacy hazard).

## Release gate

This is a **v0.7.0 source candidate / partial map milestone**. Do not claim the original v0.7.0 map synchronization scope is complete until a client component supports reversible temporary map tiles, teammate markers and deletion on leave/disconnect/restart. Main v0.6.x server remains recommended for production until NeoForge Actions build + multiplayer tests pass.
