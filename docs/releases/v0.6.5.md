# Rogler Core v0.6.5 — startup IllegalClassLoadError hotfix

**Status: source patch / JVM policy tests passed; NeoForge build and full Sable runtime test required.**

## Reproduced root cause from "Serverproblem beheben" (15 Oct 2026)

v0.6.4 registered `dev.rogler.teamwars.neoforge.compat.sable` as its Mixin package in `roglercore-sable-lifecycle.mixins.json`. It placed the **ordinary non-Mixin** runtime class `SableRemovedSublevelGuard` in that reserved package. `RoglerTeamWarsMod.started()` tried to load the class as a normal Java service, triggering an `IllegalClassLoadError` during server startup.

## Minimal fix

- Move `SableRemovedSublevelGuard.java` to `dev.rogler.teamwars.neoforge.compat` (not beneath the Mixin package).
- Update the lifecycle calls from `RoglerTeamWarsMod` and `SableCompatibilityService` to the new fully-qualified name.
- Update `SubLevelHeatMapManagerMixin` to import the relocated helper. **The Mixin class itself stays in the configured package**.
- Add `scripts/check-mixin-boundaries.py`, run automatically by `scripts/test-core.sh`, to prevent future ordinary classes being placed in this registered Mixin package.
- Bump the displayed build version, Maven archive version and CI artifact label to `0.6.5`. No registry ID, packet protocol, serialized state, config key or world storage format is changed.

## Explicit non-changes

- `Sable: Destructive` is **not** a dependency.
- The server/user setting `sub_level_splitting=true` remains enabled and is never written by this mod.
- The v0.6.4 Sable 2.0.6 removed-owner / removed-anchor guards stay intact; only class placement changes.
- FTB teams/claims, base inventory/FE/Create, raids, Warium recovery and explosion indexing are untouched.
- This startup patch does **not** prove that the earlier Sable `already removed sub-level` or Mianbao/Warium nuke crashes are solved. A dedicated test server is required.
